# 基于位置密钥的潜空间水印方案

## 1. 方案目标

本文档记录第一版可测试方案：水印不再写入公开、固定的潜空间位置，而是写入由密钥选择的潜空间子集。解码端必须用正确的位置密钥和触发词独立计算相同的位置集合及读取顺序，错误位置应得到接近随机的比特，并且不能完整恢复秘密信息。

第一版只验证机制是否成立，不声称已经具备密码学安全性，也不声称已经抵抗所有水印移除和伪造攻击。

## 2. 核心假设

Stable Diffusion v1.5 的初始潜变量形状为 `4 x 64 x 64`，共有 `N = 16384` 个标量位置。经过 RS 编码、备份和填充后的水印占用 `L < N` 个位置。

```text
位置密钥 + 触发词 + nonce + 模型标识
                 |
                 v
         确定性的密钥排列
                 |
                 v
       P = [p_1, p_2, ..., p_L]
```

第 `i` 个编码比特 `b_i` 被写入潜变量 `z[p_i]` 的符号位。图像经过生成、攻击、DDIM 反演和 INN 逆变换后，解码器重新计算 `P`，并按照相同顺序读取符号位。

预期现象：

- 正确密钥、触发词和 nonce：准确率接近固定位置的 `PLACE_SEQUENTIAL` 基线；
- 错误密钥、触发词或 nonce：原始比特准确率接近 50%，完整消息不能正确恢复；
- 密钥位置选择不应造成明显的图像质量下降。

## 3. 第一版测试范围

服务器首轮实验固定为：

- 生成模型：Stable Diffusion v1.5；
- INN：现有的 16384-bit、margin=10.0 检查点；
- 原始秘密长度：1024 bit；
- 密钥嵌入位置：从 16384 个位置中选择 8192 个；
- 数据备份：3 份；
- RS 冗余备份：请求 5 份，实际数量根据 8192 个位置的剩余容量自动确定；
- 攻击：先跑 clean，再跑 JPEG quality=25；
- 停止门样本数：每种攻击 3 张；机制正常后再扩大到 100 张；
- 同一次反演潜变量同时测试：正确位置、错误密钥、错误触发词和错误 nonce。

选择 8192 个位置是有意的。如果占满全部 16384 个位置，密钥只能控制读取顺序，不能再形成秘密的位置子集。

## 4. 嵌入流程

```text
随机生成 1024-bit 秘密信息
        |
        v
RS 冗余 + 数据/冗余备份 + 随机填充到 8192 bit
        |
        v
由密钥、触发词、nonce、模型标识生成 8192 个唯一位置
        |
        v
按照密钥顺序把比特写入潜变量符号位，margin=10
        |
        v
INN 正向变换 -> 通道归一化 -> SD v1.5 DDIM 生成
        |
        v
含水印图像
```

位置密钥和触发词从服务器环境变量读取，不能作为命令行参数传入，也不能写入 `commands.txt`、`environment.json` 或结果文件。结果中只保存位置序列的 SHA-256 指纹。

## 5. 提取流程与错误对照

```text
图像 -> 可选攻击 -> VAE 编码 -> DDIM 反演 -> INN 逆变换
                                                |
                                                v
                              独立重新计算密钥位置
                                                |
                                                v
                       符号读取 -> 多备份投票 -> RS 解码
```

评测器对同一个恢复潜变量进行四次读取：

1. 正确密钥 + 正确触发词 + 正确 nonce；
2. 派生的错误密钥；
3. 正确密钥 + 错误触发词；
4. 正确密钥 + 错误 nonce。

解码端不能复用嵌入函数返回的 `positions`。如果直接把嵌入位置交给解码器，就相当于提前泄露正确答案，不能验证本方案的核心假设。

## 6. 保存指标

正确读取和每一种错误对照都需要保存：

- 三份数据备份的原始 BER；
- 多数投票后的 BER；
- RS 解码后的最终 BER；
- RS 解码是否执行成功；
- 完整 1024-bit 消息是否完全匹配；
- 错误位置集合与正确位置集合的重叠率。

继续保存现有的生成图片、攻击图片、prompt、运行时间、GPU 显存峰值、归一化差异、命令和环境信息。

## 7. 停止门标准

只有同时满足以下条件，才能扩大到 100 张：

1. `PLACE_KEYED` 的 clean 流程完成完整的图像生成和反演闭环；
2. 正确位置准确率明显高于随机，并尽量接近固定位置基线；
3. 三种错误对照的平均比特准确率接近 50%；
4. 三种错误对照的完整消息成功次数全部为 0；
5. 输出目录存在 `samples.csv`、`summary.json`、图片、命令和环境证据；
6. 保存文件中没有出现真实位置密钥和触发词。

如果正确位置也不能恢复，不能把错误位置失败解释为方案有效。此时必须先使用相同 prompt 和 seed 跑 `PLACE_SEQUENTIAL`，区分是环境、INN、反演问题，还是密钥位置导致的问题。

## 8. AutoDL 配置与运行

以下内容只加入服务器的 `.env`，不要提交真实 `.env`：

```bash
MAXMARK_POSITION_KEY=replace-with-at-least-16-bytes
MAXMARK_POSITION_TRIGGER=owner-a
KEYED_EMBEDDING_SLOTS=8192
KEYED_EVAL_NUM_SAMPLES=3
```

运行顺序：

```bash
bash scripts/run_autodl.sh preflight
bash scripts/run_autodl.sh minimal
bash scripts/run_autodl.sh subset-minimal
bash scripts/run_autodl.sh keyed-minimal
```

`minimal` 是原始16384个位置的基线；`subset-minimal` 使用同样的8192-bit编码负载，但固定放在前8192个位置；`keyed-minimal` 则把相同负载放入密钥生成的8192个位置。三个停止门都成功并检查 clean/JPEG 输出以后，才扩大样本量。

## 9. 当前证据边界

本地测试只能证明位置生成具有确定性、位置不重复，并且在未经过扩散的理想潜变量上只有正确位置能够按顺序恢复全部比特。本地没有执行 Stable Diffusion 生成、DDIM 反演或 GPU 端到端实验。

服务器三张图片的成功结果也只能证明代码已经正确接线，不能证明统计鲁棒性或安全性。正式结论至少需要 100 张正确/错误位置对照、多组独立位置密钥、攻击测试和图像质量比较。

每图随机 nonce、消息认证、位置重叠比例扫描、多图片统计攻击以及水印移除/伪造攻击，留到基础位置依赖机制确认以后再加入。
